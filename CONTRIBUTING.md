# Contributing

Open an issue for format changes before expanding the vocabulary. Small fixes and examples are welcome. Keep examples short and give every budget a concrete reason.

## Development

Install stable Rust and Python 3 (only for the static website).

```sh
cargo fmt --check
cargo test --locked --all-features
cargo test --locked --no-default-features
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo run --locked --features cli -- check examples
cargo run --locked --example schema --features schema > schema/document.schema.json
cargo run --locked --example runtime_schema --features schema,runtime -- request > schema/request.schema.json
cargo run --locked --example runtime_schema --features schema,runtime -- usage > schema/usage.schema.json
python3 site/build.py
```

The schema is generated from Rust types; commit changes to it with type changes. API pages are generated by `cargo doc`. The website has no npm dependencies. The public site at `htmlp.dev` uses the root path (empty `HTMLP_BASE_PATH`). For a project subpath, set `HTMLP_BASE_PATH` explicitly.

After an intentional example budget change, run `cargo run --features cli -- sign examples` and review the diff. Do not add automatic signing to CI.

## Editor diagnostics

Install the CLI, then run `htmlp watch ./prompts`. In VS Code, use the included **HTMLP: watch current file** task. It runs the installed `htmlp` binary and attaches errors to the Problems panel. This is a task integration, not a marketplace editor extension. `.htmlp` is the filename extension.

Watch uses 500 ms content polling without an additional watcher dependency. For very large trees, watch the relevant prompt directory. Use `htmlp check` in CI; watch does not terminate on validation errors.

## Releases

The MIT-licensed crate is currently distributed through GitHub source and release artifacts. Do not claim crates.io installation until publication exists. Version changes must update Cargo metadata, documentation, schema, and examples. Release binaries should include the target/ABI, checksums, and a description of how they were built. Do not commit credentials or generated build directories.

Follow the [code of conduct](CODE_OF_CONDUCT.md). See [SECURITY.md](SECURITY.md) for private vulnerability reporting.
